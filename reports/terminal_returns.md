# 以整盘胜率检验新的猜格策略

评测使用经典八邻域专家盘，16 行、30 列、99 雷，每盘均匀随机首点，首点及邻格安全。每个种子固定雷图与首点。确定步由求解器完成，猜格只读取当时可见的棋盘和剩余雷数。每盘计一次胜或负。以下为模拟器对弈。

## 桌面默认策略

| 独立测试起始种子 | 盘数 | 桌面旧版胜局 | 小残局复核胜局 | endgame 胜局 |
|---|---:|---:|---:|---:|
| [4300000](midgame_returns_test.json) | 4,096 | 2,135 | 2,162 | 2,159 |
| [4500000](partition_guesses_test.json) | 4,096 | 2,045 | 2,084 | 2,110 |
| [4700000](swap_guesses_test.json) | 4,096 | 2,124 | 2,141 | 2,121 |
| [4800000](swap_guesses_replication.json) | 4,096 | 2,044 | 2,055 | 2,045 |
| 合计 | 16,384 | 8,348（50.95%） | 8,442（51.53%） | 8,435（51.48%） |

小残局复核在四批新种子上分别比桌面旧版多赢 27、39、17、11 盘。合计复核版独赢 169 盘、旧版独赢 75 盘，净增 94 盘，配对胜率差为 +0.57 个百分点，按棋盘配对重采样的 95% 区间为 +0.39 至 +0.76 个百分点。相对 endgame 多赢 7 盘，配对区间为 −0.61 至 +0.71 个百分点。复核版总体胜率的 Wilson 95% 区间为 50.76% 至 52.29%。开发集与以前公布的样本都未计入此表。

## 中盘的同局面分支训练

从 1,536 张训练雷图上自然走到必须猜的局面，最多取每盘一个位置。按种子交替取首个符合条件的位置，或跳过第一个再取。范围为剩余未知格至多 120 个且超出小残局复核范围。350 个位置有至少两个不同的提议。候选包括整盘模型选格，以及按雷率、可能开空、揭示数字的信息量和能直接确定邻格的概率提出的格子。估计这些特征时每盘独立抽取 64 张与可见信息相容的雷图。

每个位置再用独立随机流抽取 16 张相容雷图，每个候选在同一组雷图上分别点第一步，然后由确定步求解器和冻结的整盘模型一直玩到终局。共 5,600 张抽样雷图、17,392 条候选分支。其中 1,270 张雷图上，至少两个候选的最终胜负不同。训练目标是候选相对原落点的实际获胜率差；其他求解器的选格未用作标签。后续推演用基础模型，正式测试则与桌面使用的小残局复核一起运行。

为限制过拟合，只拟合七个共享系数，同一训练局面总权重相等，使用岭回归收缩系数。预测终局胜率差至少 2.5 个百分点才改动原落点。开测前固定门槛、特征和权重。训练起始种子 4100000，开发验证 4200000，独立测试 4300000。[训练代码](../experiments/midgame_returns.py) · [系数和训练规模](midgame_returns_model.json)

| 策略 | 开发验证胜局 / 512 | 独立测试胜局 / 4,096 |
|---|---:|---:|
| 桌面旧版 | 259 | 2,135 |
| 小残局复核 | 261 | 2,162 |
| 小残局复核加中盘模型 | 261 | 2,162 |

独立测试中，中盘模型检查了 2,692 次猜格，在 18 盘中换格 19 次。相对小残局复核，它独赢 1 盘、独输 1 盘，差值为 0.00 个百分点，配对自助法 95% 区间为 −0.07 至 +0.07 个百分点。这组结果支持继续使用小残局复核。更多中盘分支是否有益仍需独立验证。[开发集逐盘结果](midgame_returns_dev.json) · [测试集逐盘结果](midgame_returns_test.json)

小残局复核相对桌面旧版独赢 43 盘、独输 16 盘，净增 27 盘。胜率由 52.12% 升至 52.78%，配对差值为 +0.66 个百分点，95% 区间为 +0.29 至 +1.03 个百分点，精确 McNemar 检验 p = 0.000584。复核版整盘胜率的 Wilson 95% 区间为 51.25% 至 54.31%。桌面端的猜格说明会区分当下踩雷概率和选格后的终局获胜数。[逐盘结果与配对检验](midgame_returns_test.json)

## 搜索更大的残局

Java 求解器的深度分析会在相容雷图较少时搜索整局胜率。这里独立实现了按可见结果分组的搜索。每格点开后能看到的数字和开空区域把相容雷图分成若干组。后续走法可以根据玩家看到的结果选择；两条路线若剩下完全相同的一组雷图，就复用已经算出的获胜数。已翻开的格子在该组内提供恒定观测；如果只剩一种雷图，所有安全格都可以确定。[Java 求解器作者的说明](https://github.com/DavidNHill/Minesweeper#5-brute-force-deep-analysis) · [分组搜索实现](../ms/world_partitions.py)

在小残局复核尚未完成全部比较时，实验策略允许最多 52 个未知格、2,048 张相容雷图，枚举和搜索的工作量上限分别为 65,536 和 250,000。只有原格和新格在最优后续走法下的终局获胜数都已算清、新格严格更好时才换。若算不完原格，则沿用小残局策略。用独立的小棋盘模拟器逐格核对获胜数，覆盖开空、旗子、问号和需要牺牲即时存活率的局面。[逐格验证](../tests/test_endgame.py)

从种子 4500000 开始的另一批 4,096 盘里，扩展搜索赢 2,083 盘，小残局复核赢 2,084 盘，桌面旧版赢 2,045 盘，endgame 赢 2,110 盘。扩展搜索在 115 盘换格，独赢 13 盘、独输 14 盘，配对差值为 −0.02 个百分点，95% 区间为 −0.27 至 +0.22 个百分点。精确分数假定后续能走最优步；实际执行仍受每一步的搜索预算限制。扩展范围未进入桌面默认策略。[逐盘结果](partition_guesses_test.json)

## 特定雷图里的二选一

考虑两个横向或纵向相邻的未知格。若其中恰有一雷，并且所有只能邻接其中一格的外部位置也都是雷，那么把这一雷交换到另一个格子，玩家在其余所有安全格上看到的数字都相同。这些相容雷图成对出现。在这部分雷图上，玩家无论等到什么时候才点这对格子，都有一次无法靠数字分辨的二选一。JavaScript 求解器作者也讨论了只有在某些布局中才会出现的二选一。[作者对条件二选一的说明](https://github.com/DavidNHill/JSMinesweeper)

对超出小残局复核范围的猜格，实验程序筛出最多还需确定两个外部位置的相邻格对，抽取 96 张相容雷图。对每格取最强一对，以单个格对二选一频率的 Wilson 下界的一半估计不可避免的风险，同一格涉及多个格对时不重复累计。风险调整后比原选格低至少 4 个百分点才换，模型在距最佳调整值 1 个百分点以内的候选中选格。调整量只用于候选排序，落点的踩雷概率单独按边际雷率记录。首批结果揭晓前已按同一配置启动另一批独立验证。[实现](../experiments/swap_guesses.py)

两批共 8,192 盘，其中 904 盘改变了走法。条件二选一策略分别赢 2,140 和 2,053 盘，小残局复核分别赢 2,141 和 2,055 盘。双方有 65 盘胜负相反，条件二选一独赢 31 盘、独输 34 盘，胜率差为 −0.04 个百分点，配对 95% 区间为 −0.23 至 +0.16 个百分点。许多换格只改变了之后的走法，最终胜负相同。这条估算规则保留在实验中。[第一批逐盘结果](swap_guesses_test.json) · [独立复验](swap_guesses_replication.json)

```powershell
python -m experiments.midgame_returns train --seed 4100000 --games 1536 --draws 16 --model reports/local/returns.json --out reports/local/returns_training.json

python -m experiments.midgame_returns eval --seed 4300000 --games 4096 --model reports/local/returns.json --out reports/local/returns_test.json
python -m experiments.partition_guesses --seed 4500000 --games 4096 --jobs 10 --out reports/local/partitions_test.json
python -m experiments.partition_guesses --method swap --seed 4700000 --games 4096 --jobs 14 --out reports/local/swaps_test.json
python -m experiments.partition_guesses --method swap --seed 4800000 --games 4096 --jobs 10 --out reports/local/swaps_replication.json
```
